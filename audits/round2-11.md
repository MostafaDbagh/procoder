# Round 2–11: revalidation and discovery

Read-only source audit; no application edits or authenticated mutations. Checked installed Next 16.2.3 docs: `node_modules/next/dist/docs/01-app/03-api-reference/04-functions/revalidatePath.md` and `after.md`. Route-handler invalidation takes effect on the next visit, applies to the specified page, and is not a blanket descendant purge.

## Verified actionable findings

1. **P1 — Blog saves invalidate and announce the wrong URLs.** `src/app/admin/dashboard/AdminDashboard.tsx:3432` sends `/en/blog` and `/ar/blog`, while the actual routes are `[locale]/blogs/page.tsx` and `[locale]/blogs/[slug]/page.tsx`. `src/app/api/revalidate/route.ts:68,79` passes these directly to `revalidatePath` and IndexNow. Consequently edits do not invalidate the actual cached blog listing/detail, and IndexNow receives nonexistent singular URLs. Send `/en/blogs`, `/ar/blogs`, and both localized old/new article URLs; retain the prior slug when renamed. Verify after warming caches, publishing/editing/renaming, then requesting each affected route.

2. **P2 — Course mutation invalidation omits the edited detail pages.** The dashboard helper at lines 758–768 defaults to only locale homes and course listings; course save/delete flows invoke that default (lines 981,1009,3367,3381). The detail page explicitly expects localized detail invalidation (`src/app/[locale]/courses/[id]/page.tsx:13`) but none is supplied. Invalidation of `/en/courses` as a page does not invalidate its children. Pass both localized detail paths, including old slug on renames/deletes, alongside listings; submit affected detail URLs to IndexNow. Impact is bounded by existing timed ISR under healthy backend conditions, but immediate admin refresh is currently false.

3. **P2 — Discovery files are outside the mutation invalidation set.** No dashboard invocation or default handler path includes `/sitemap.xml`, `/llms.txt`, or `/llms-full.txt`. The sitemap has a separately cached paginated blog fetch with a six-hour TTL (`src/app/sitemap.ts:6,25–26`); editing the ordinary blog page does not invalidate that distinct fetch. AI files independently advertise one day of shared-cache freshness plus a seven-day stale-while-revalidate window (`src/app/llms.txt/route.ts:20`, `src/app/llms-full.txt/route.ts:20`). Deleted or newly published content can therefore diverge from discovery even after public-page invalidation. Explicitly invalidate the sitemap and its data on publication/catalog mutations; align AI response cache lifetime with desired freshness and use the hosting CDN's supported purge mechanism if immediate removal is required. Do not assume Next path invalidation purges every external CDN cache. No claim that sitemap's *entire output* always remains stale for six hours: its course fetch has a shorter interval.

4. **P2 — IndexNow side effect is not lifecycle-protected and failures are invisible.** `src/app/api/revalidate/route.ts:77–84` starts an unawaited request, ignores HTTP failure responses, and swallows rejection before returning success. Completion is not guaranteed when a serverless invocation ends; the response also cannot establish notification success. Use installed Next's `after(async () => { ... })` with awaited fetch and observable error handling, or await/enqueue the submission. This is a verified implementation risk, not evidence of observed production delivery loss.

Prioritize findings 1–3; discovery freshness matters more than the optional IndexNow optimization. No tests run: findings are directly traced source paths and framework documentation, not production cache observations.
