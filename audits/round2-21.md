# Round 2–21: server-fetch reliability

Read `AGENTS.md`; application files unchanged. Reviewed public server getters and consumers. Verified getter behavior by transpiling the current `server-api.ts` with installed TypeScript and executing it with a mocked fetch; no production outage is claimed. Excludes the already-fixed missing-await JSON rejection issue.

1. **P2 — The shared layout's course fetch has no request deadline, so even unrelated public pages can stall on a slow backend.** `src/lib/server-api.ts:150–158` supplies revalidation but no abort signal; `src/app/[locale]/layout.tsx:54` awaits it before rendering every localized page. Both course detail fetch (`server-api.ts:180–182`) and blog-list/sitemap requests likewise lack deadlines. Even blog detail's explicit eight-second timeout cannot bound rendering: its sibling course request is awaited in `Promise.all` (`blogs/[slug]/page.tsx:66–69`), and the shared layout also waits for courses. A backend accepting connections but not finishing the response can consume platform/request timeouts instead of reaching existing fallbacks promptly. The executed probe confirmed no signal for both course getters. Apply a bounded timeout covering headers and body to all server fetches, retaining each caller's existing unavailable-versus-not-found behavior.

2. **P2 — Valid JSON `null` from an HTTP 200 blog detail response becomes a false not-found.** `src/lib/server-api.ts:287–289` checks HTTP status and then returns decoded JSON without validating the entity. Executing the actual getter with `new Response('null', {status: 200})` returned `null`; `src/app/[locale]/blogs/[slug]/page.tsx:72` subsequently calls `notFound()`. This contradicts the helper's contract that only an upstream 404 establishes deletion. Other invalid entity shapes can instead crash metadata/body rendering through required-field accesses. Validate the minimum post shape and throw `ApiUnavailableError` for invalid successful payloads, reserving null for explicit HTTP 404. This is a response-contract failure case, not evidence that the current backend ordinarily returns null.
