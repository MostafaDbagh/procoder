# Round 2-15 — Canonical origins and hreflang

Read-only application audit; read AGENTS.md. Evidence is current source and executed installed-library helpers, not a new production crawl.

1. **P2 — HTTP hreflang conflicts with HTML/sitemap declarations.** `src/i18n/routing.ts:3–8` leaves next-intl `alternateLinks` enabled (installed `node_modules/next-intl/dist/esm/development/routing/config.js:7` defaults it to true); `src/proxy.ts:30–36` returns that response unchanged. Executing installed `getAlternateLinksHeaderValue` with NextRequest for `/en/courses` emits `en=/en/courses`, `ar=/ar/courses`, **`x-default=/courses`**, while `src/lib/seo.ts:125–135` and sitemap use **`x-default=/en/courses`**. `/courses` is a locale redirect, not the canonical landing URL. More materially, executing the helper for `/en/blogs?page=2` emits `/en/blogs` and `/ar/blogs` without pagination, whereas archive HTML deliberately preserves `?page=2` (`src/app/[locale]/blogs/page.tsx:30–33,60`). Query variants also retain HTTP hreflang even when `metaForMaybeVariant` explicitly omits HTML hreflang (`seo.ts:101–118`). Disable automatic HTTP alternates and rely on consistent HTML/sitemap, or construct matching canonical-aware headers.

2. **P2, configuration-dependent — documented origin conflicts with forced www redirect.** `.env.example:2` recommends `SITE_URL=https://stemtechlab.com`; `seo.ts:36–38` accepts it verbatim, and the sitemap uses the same helper (`src/app/sitemap.ts:68–75`). `next.config.ts:48–54` permanently redirects this host to `https://www.stemtechlab.com`. Executed seo helper with the documented value: canonical and all language alternates point to non-www redirect destinations. Current `.env.production:5` and default correctly use www, so this is a reproducible deployment trap, not evidence production currently has wrong canonicals. Correct the example and validate/canonicalize the configured origin consistently.

3. **P3, configuration-dependent — trailing-slash normalization differs across consumers.** `seo.ts:38` and StructuredData strip one final slash, but `src/app/robots.ts:4,62–63`, `src/app/layout.tsx:42,122–123,155–161`, and many page modules concatenate the raw environment value. With `SITE_URL=https://www.stemtechlab.com/`, canonical `/en/courses` remains clean while robots advertises `https://www.stemtechlab.com//sitemap.xml`, and root discovery links contain doubled path slashes. `.env.example:1` already requests no trailing slash and current production value complies; consolidate consumers onto one normalized origin to prevent drift.

Passing scope checks: default/production origins consistently use HTTPS www; public route helpers have reciprocal `en`/`ar`, self-referencing canonical, and English x-default; sitemap uses the same locale paths; no configured trailingSlash override, and installed Next.js trailingSlash documentation confirms slash-to-no-slash redirection by default. No app files changed.
